## 4단계. 사이트 구성 기획 (코드 작성 전에 정할 것)

코드를 쓰기 전에 아래 내용을 정해 두면, 이후 단계는 이 결정을 데이터 파일로 옮기기만 하면 됩니다.

### 4-1. 대분류·소분류 정하기
- 처음에는 대분류 3~4개, 대분류마다 소분류 3~5개로 작게 시작합니다.
- 각 분류에 **화면용 이름**(한국어)과 **주소용 이름(slug, 영문 소문자·하이픈)**을 정합니다. slug는 URL이 되므로 나중에 바꾸지 않는 것이 좋습니다.
- 아래 초안대로 `src/data/categories.json`에 작성함 (2026-11-17):

| 대분류 (slug) | 소분류 (slug) |
|---|---|
| 야구 응원 (`cheering`) | 응원 타월 (`towel`), 머리띠·모자 (`headwear`), 담요·방석 (`blanket`), 클래퍼·응원봉 (`clapper`) |
| 크리스마스 (`christmas`) | 홈데코 (`home-deco`), 파티 소품 (`party`), 니트·의류 (`knit`) |
| 영화 무드 (`movie-mood`) | 80년대 레트로 (`retro`), 누아르 (`noir`), 우주 SF (`space`) |

- 야구 응원은 **구단별로 나누지 않습니다.** 색상 계열과 용품 종류로 나누고, 색상은 필터로 고르게 합니다. (CLAUDE.md 상품·문구 규칙)

### 4-2. 태그 사전 (초안 작성: `src/data/tags.json`)
태그는 아무렇게나 붙이면 "레드/빨강/빨간색"처럼 흩어지므로, 쓸 수 있는 태그 목록을 미리 정해 둡니다.
- 태그마다 `id`(주소용 영문, 예: `/tags/red`)와 `name`(화면용 한국어)이 있습니다.
- **색상** 18개: 레드, 오렌지, 옐로, 그린, 민트, 스카이블루, 블루, 네이비, 퍼플, 핑크, 브라운, 베이지, 블랙, 화이트, 그레이, 골드, 실버, 멀티컬러
- **소재** 12개: 면, 니트, 플리스, 벨벳, 데님, 인조가죽, 나일론, 우드, 아크릴, 유리, 메탈, 종이
- **스타일·무드** 14개: 레트로, 빈티지, 미니멀, 모노톤, 네온, 메탈릭, 글리터, 포근한, 클래식, Y2K, 체크 패턴, 스트라이프, 도트, 동물 모티브
- **용도** 9개: 응원, 홈파티, 선물, 인테리어, 포토 소품, 야외, 우천 대비, 겨울 보온, 데일리
- 브랜드·구단·캐릭터 이름은 태그로 쓰지 않습니다. 새 태그가 필요하면 `tags.json`에 먼저 추가합니다.
- "동물 모티브" 상품은 특정 구단을 떠올리게 하는 구성(팀 수에 맞춘 배치, 팀 색 조합)을 피합니다.

### 4-3. 가격대 구간 (초안 작성: `src/data/price-ranges.json`)
| id | 화면 표시 | 범위 |
|---|---|---|
| `under-10k` | 1만원 이하 | 0 ~ 10,000원 |
| `10k-20k` | 1~2만원 | 10,001 ~ 20,000원 |
| `20k-30k` | 2~3만원 | 20,001 ~ 30,000원 |
| `30k-50k` | 3~5만원 | 30,001 ~ 50,000원 |
| `over-50k` | 5만원 초과 | 50,001원 ~ |

- 가격은 자주 바뀌므로 정확한 금액 대신 **가격대**를 보여 줍니다.
- 카테고리 페이지의 가격대 필터도 이 구간을 그대로 씁니다.

### 4-4. 상품 데이터 형식 정하기
`src/data/products.json`의 상품 하나는 아래 모양으로 합니다.

```json
{
  "id": "cheer-towel-red-stripe",
  "name": "레드 스트라이프 응원 타월",
  "category": "cheering",
  "subcategory": "towel",
  "tags": ["red", "stripe", "cotton", "cheering"],
  "color": "red",
  "priceRange": "under-10k",
  "seller": "오픈마켓",
  "url": "https://...",
  "image": "https://판매처의-상품-이미지-주소.jpg",
  "addedAt": "2026-11-17"
}
```

- `id`: 상품마다 겹치지 않는 영문 이름 (주소·정렬에 사용)
- `tags`: `tags.json`에 있는 태그 `id`만 사용
- `color`: 카테고리 페이지 색상 필터용 (`tags.json` 색상 그룹의 `id` 중 하나)
- `priceRange`: `price-ranges.json`의 `id` 중 하나
- `image`: 판매처 상품 이미지 주소 (없으면 `null` → 색상 카드로 표시)
- `addedAt`: "새로 추가된 순" 정렬과 "새 상품" 표시용

### 4-5. 상품 이미지 방식 (결정: 임베딩)
- 판매처 상품 페이지의 이미지 주소를 `products.json`의 `image`에 적고, 사이트에서는 그 주소를 그대로 불러와 보여 줍니다(임베딩). 이미지 파일을 저장소에 저장하지 않습니다.
- 지킬 것:
  - 이미지를 내려받아 저장하거나, 자르기·편집·AI 재생성을 하지 않음
  - 브랜드 로고, 모델 얼굴, 공식 화보가 보이는 이미지는 쓰지 않음 (그런 상품은 `image: null`)
  - 판매처가 외부 표시를 막아 둔 이미지는 우회하지 않고 `null`로 둠
- 대비할 것:
  - 이미지가 깨지거나 주소가 바뀌면 자동으로 색상 카드로 바뀌게 만듦
  - 판매처 요청이 있으면 바로 `image`를 `null`로 바꾸거나 상품을 삭제
- 참고: 임베딩도 저작권 분쟁이 생길 수 있음 (해외 비교 사이트가 상품 사진 문제로 소송을 당한 사례 있음)

### 4-6. 그 밖에 정할 것
- 사이트 분위기: 기본 색, 글꼴 느낌 (예: 밝고 깔끔한 톤 + 테마마다 포인트 색)

**완료 기준**: 위 내용이 정해져서 `categories.json` 초안과 태그 목록을 만들 수 있는 상태.

## 5단계. Astro 뼈대 설치 + 배포 설정

### 5-1. Astro 설치 (완료: 2026-11-17)
- Astro `7.4.12`를 버전 고정으로 설치 (Node.js 22.23.4 이상 필요)
- `astro.config.mjs`에 GitHub Pages 주소 설정:
  - `site: "https://non-tight.github.io"`
  - `base: "/stylehub"` (사이트가 하위 경로에 있으므로 필수)
- 명령어: `npm run dev`(개발 서버), `npm run check-data`(데이터 검사), `npm run build`(검사 + 빌드), `npm run preview`(빌드 결과 미리보기)

### 5-2. 폴더 구조 (★ = 5단계에서 만든 것)
```
.github/workflows/deploy.yml  ★ 배포 자동화
scripts/check-data.mjs        ★ 데이터 검사
src/
  data/
    categories.json     ★ 대분류·소분류
    tags.json           ★ 태그 사전
    price-ranges.json   ★ 가격대 구간
    products.json       ★ 상품 목록 (지금은 빈 목록)
    banned-words.json   ★ 금지 단어 목록
  lib/
    data.ts             ★ JSON 불러오기 + 타입 + 도우미 함수
    url.ts              ★ 링크 앞에 /stylehub 붙이는 withBase()
  layouts/
    BaseLayout.astro    ← 모든 페이지 공통 틀 (7단계)
  components/
    Header.astro        ← 7단계
    Footer.astro        ← 하단 안내문 (7단계)
    ProductCard.astro   ← 상품 카드 (7단계)
    ThemeTile.astro     ← 홈 테마 타일 (8단계)
    ProductRow.astro    ← 홈 가로 줄 (8단계)
  pages/
    index.astro                       ★ 홈 (지금은 임시 "준비 중" 화면)
    category/[category]/index.astro   ← 대분류 페이지 (9단계)
    category/[category]/[sub].astro   ← 소분류 페이지 (9단계)
    tags/index.astro                  ← 전체 태그 (10단계)
    tags/[tag].astro                  ← 태그별 상품 (10단계)
    about.astro                       ← 소개 (10단계)
```

> **Next.js와 비교**: Astro도 `src/pages` 폴더 구조가 곧 주소가 되는 방식이라 Next.js의 pages 라우터와 거의 같습니다. `[category].astro`는 Next.js의 `[category].js` 동적 페이지와 같고, `getStaticPaths()`도 Next.js와 이름·역할이 같습니다. 다른 점은 Astro는 기본적으로 **자바스크립트 없이 HTML만** 만들어 낸다는 것이고, 필요한 부분에만 스크립트를 붙입니다.
>
> 링크 주의: Next.js의 `basePath`는 `<Link>`에 자동으로 붙지만, Astro는 `<a href>`에 `/stylehub`를 자동으로 붙여 주지 않습니다. 사이트 안쪽 링크는 항상 `withBase("/tags/red")`처럼 씁니다.

### 5-3. 데이터 불러오기와 검사 (변경: 콘텐츠 컬렉션 대신 JSON import + 검사 스크립트)
- 콘텐츠 컬렉션은 파일 하나 안의 형식만 검사하므로, 파일끼리 맞춰 보는 검사(상품 태그가 tags.json에 있는지 등)를 위해 별도 스크립트로 바꿈
- **`src/lib/data.ts`**: JSON을 import해서 타입과 도우미 함수(`getProductsBySub()`, `getTag()` 등)로 제공. 페이지에서는 이 파일만 사용
- **`scripts/check-data.mjs`**가 검사하는 것:
  - 필수 항목, id 형식(영문 소문자·숫자·하이픈)과 중복
  - 대분류·소분류·태그·색상·가격대가 사전 파일에 있는 값인지
  - `url`은 `https://`, `image`는 `https://` 또는 `null`, `addedAt`은 `2026-11-17` 형식
  - 금지 표현: `banned-words.json`의 단어("정품급", "미러급", "레플리카" 등), "OO st" 형태
- 브랜드·구단·캐릭터 이름은 `banned-words.json`의 `terms`에 추가하면 상품명·판매처명·분류명·태그명에서 잡아냄
- `npm run build`는 **검사 → 빌드** 순서. 검사에 실패하면 빌드·배포가 멈춤

### 5-4. GitHub Actions 배포 설정
- `.github/workflows/deploy.yml`: `main`에 push되면(또는 Actions 탭에서 수동 실행) 설치 → 검사 + 빌드 → GitHub Pages 배포
- GitHub 공식 액션(checkout, setup-node, upload-pages-artifact, deploy-pages)을 직접 나열해서 각 단계가 보이게 함. Node.js 24 사용
- 저장소 **Settings → Pages → Source를 "GitHub Actions"**로 변경 (사용자가 직접 해야 하는 설정, 6단계)

**완료 기준**: `npm run build` 성공, 틀린 데이터를 검사가 잡아냄, `npm run preview`에서 `/stylehub/` 주소로 임시 화면이 뜸, 배포 워크플로 파일 준비. (2026-11-17 모두 확인)

## 7단계. 공통 레이아웃 (완료: 2026-11-17)
- **디자인 토큰** (`src/styles/global.css`): 밝은 쿨그레이 배경 + 흰 카드 + 코발트 블루 포인트. 색·글자 크기·간격·모서리를 변수로 모음. 다크 모드는 나중에 이 변수를 다시 정의해서 추가
- **글꼴**: Pretendard (npm 패키지, OFL 라이선스). 필요한 글자 범위만 나눠 불러오는 방식이라 첫 화면이 가벼움
- **BaseLayout** (`src/layouts/BaseLayout.astro`): 제목("페이지 | 스타일허브"), 설명, canonical, 링크 공유 정보(og:*), 파비콘, `noindex` 옵션, "본문으로 건너뛰기" 링크
- **Header**: 로고 + 메뉴(홈 / 대분류들 / 태그 / 소개). 대분류 메뉴는 categories.json에서 자동 생성, 현재 메뉴 강조, 휴대폰에서는 가로로 밀어 보는 메뉴 줄. 검색은 11단계 이후 선택 기능
- **Footer**: 아래 안내문 + 하단 메뉴 + © 표시 (이미지 안내 문구는 넣지 않음)
  > 스타일허브는 상품을 직접 판매하지 않으며, 제휴 링크를 통한 수수료도 받지 않습니다.
  > 각 상품의 정보·가격·배송·교환·환불은 해당 판매처의 책임입니다.
- **ProductCard**: 이미지(또는 색상 카드), 상품명(최대 2줄), 가격대 · 판매처, 태그(최대 3개, 태그 페이지 링크), "판매처 보기 ↗" 버튼
  - 이미지는 판매처 주소에서 불러오고(`loading="lazy"`), 없거나 불러오기에 실패하면 색상 카드(상품 `color` 색 + 소분류 이름)가 보임. 색 코드는 `src/lib/colors.ts`
  - 이미지와 상품명을 한 링크로 묶고 이미지 alt는 비워 둠 (화면 낭독기가 상품명을 두 번 읽지 않게. 브랜드명이 alt에 들어갈 일도 없음)
  - 외부 링크는 새 탭으로 열고 `rel="noopener noreferrer nofollow"` 적용
- **개발용 미리보기** (`src/pages/dev/[name].astro`): `npm run dev`일 때만 `/stylehub/dev/components`에서 예시 카드 확인. 배포용 빌드에는 만들어지지 않음
- 홈 임시 화면을 BaseLayout으로 감쌈. 메뉴의 테마·태그·소개 링크는 9~10단계 전까지 404

**완료 기준**: 헤더·하단이 모든 페이지에 보이고, 미리보기 페이지에서 카드(이미지 / 깨진 이미지 / 이미지 없음 / 긴 상품명)가 정상 표시됨. PC·휴대폰 너비에서 가로 스크롤 없음. (2026-11-17 확인)

## 8단계. 홈 페이지 (테마 타일 + 가로 줄)

**완료 기준**: 데이터에 대분류·상품을 추가하면 홈에 자동으로 나타남.

## 9단계. 카테고리 페이지 (목록형)
- `category/[category]/[sub]` 주소로 소분류마다 페이지 자동 생성 (`getStaticPaths`)
- 왼쪽: 대분류·소분류 메뉴 (현재 위치 강조), 휴대폰에서는 위쪽으로 이동
- 위쪽: 위치 표시(야구 응원 › 응원 타월 · 24개), 정렬(새로 추가된 순)
- **색상·가격대 필터**: 정적 사이트라 서버가 없으므로, 화면에서 작은 스크립트로 카드를 보이기/숨기기
- 대분류 페이지(`category/[category]`)는 그 아래 전체 상품을 같은 방식으로 표시

**완료 기준**: 모든 소분류 페이지가 생성되고 필터가 동작함.

---

## 10단계. 태그 페이지, 소개 페이지
- `tags/[tag]`: 태그마다 상품 목록 페이지 자동 생성
- `tags/`: 전체 태그를 종류별(색상·소재·스타일·용도)로 모아 보여 줌
- `about`: 사이트 소개, 판매하지 않음·수수료 없음 안내, 상품 이미지는 판매처 이미지를 불러와 표시한다는 안내
- 404 페이지

**완료 기준**: 사이트의 모든 메뉴가 연결되고 끊긴 링크가 없음.

---

## 11단계. 상품 추가·수정 반복
- 상품 추가는 `products.json`에 항목을 넣는 것만으로 끝 (페이지는 자동 생성)
- 추가할 때마다 확인: 브랜드·구단·캐릭터명 없음, 금지 표현 없음, 태그는 태그 사전 안에서만
- 야구 응원 상품: 특정 구단을 떠올리게 하는 묶음(팀 수에 맞춘 배치, 팀 색 조합) 피하기
- 필요해지면 선택 기능 추가: 검색, "새 상품" 표시, 공유 버튼

---

## 12단계. 예약 작업(링크 점검) 설정
- 판매처 링크가 사라지거나(404) 품절 페이지로 바뀌는지 주기적으로 점검
- GitHub Actions 예약 실행(예: 매주 1회)으로 모든 상품 링크와 이미지 주소를 확인하고, 문제가 있으면 이슈로 알림
- 문제가 생긴 상품은 직접 확인 후 수정·삭제
